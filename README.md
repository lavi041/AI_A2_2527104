## Problem
A Musanze potato cooperative receives farm records in inconsistent spreadsheets. This system (1) estimates
harvest quantity (**regression**), (2) flags farms at high production risk (**classification**: yield per hectare
below the median) and (3) groups farms with similar conditions (**clustering**). Training and CLI prediction work
fully offline; a FastAPI service is provided for later mobile-app integration.

## Design summary
* **Leakage control:** `yield_tons`, yield per hectare and `high_risk` are never inputs (`assert_no_leakage`).
* **Train-only fitting:** imputer, scaler and encoder live inside one `Pipeline`/`ColumnTransformer`, fitted on the
  training split only; the same pipeline is saved and used for inference.
* **Model selection:** 5-fold cross-validation on the training split (RMSE for regression, F1 for classification).
  The test set is used only for final reporting.
* **Clustering:** KMeans on scaled features (no targets), K = 2..6, K chosen by silhouette.

Invalid input returns HTTP **422** with `{"error": "validation_error", "detail": [{"field", "message", "type"}]}`;
submitted values are never echoed back. Missing models return **503**.

## Known limitations
* Data is synthetic and uniformly distributed; real farms will differ (drift, correlated features, noisy records).
* Linear regression wins because the generator is almost linear; this will not necessarily hold for real data.
* Clusters are weak (silhouette about 0.17): they are practical groupings, not natural segments.
* Inputs outside the training ranges are rejected on purpose (the model was never trained there).
* Final models are trained on the training split only (so reported metrics describe the saved models).
* Not for decisions about finance, insurance or public services. A human (field officer/agronomist) must review.
